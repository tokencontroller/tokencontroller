# Prices come from LiteLLM's list, with our own rows on top

The managed price table (ADR 0024) is no longer a list we keep by hand. It is LiteLLM's price list (`model_prices_and_context_window.json` in github.com/BerriAI/litellm, MIT licence), which its maintainers keep for thousands of models across more than a hundred providers, mapped to our providers and token kinds, with a short file of our own rows on top. Both are built into the service, so every edition, hosted, Enterprise and open, prices the same models the same way.

- `prices/litellm.csv` is generated by `scripts/prices/update.py` from one LiteLLM commit (`prices/litellm-commit`). The script is the only place that knows LiteLLM's format. It keeps text models only, maps LiteLLM's provider keys to ours from a fixed table (the provider is never guessed, ADR 0028), strips LiteLLM's provider prefix from the model name, turns prices per token into prices per million, and leaves out zero prices and names two entries price differently.
- Rows stay records. A price seen before keeps its row; a changed price becomes a new row valid from the day it is read; a model LiteLLM drops keeps its rows; a model seen for the first time is valid from 2025-01-01, the first day of the old hand-kept table.
- `prices/overrides.csv` is ours. For its provider, model and kind it replaces every LiteLLM row (`price_table::built_in`). It holds the models LiteLLM lacks today. If LiteLLM stops keeping its list, we stop refreshing and keep prices in this file alone; nothing else changes.
- The service stores the built-in rows into `managed_price_rows` at start and every 15 minutes, then the self-hoster's `TC_PRICE_TABLE` file, whose row wins on the same provider, model, kind and valid-from date. An organization's rows and a contract's rows still win over both (ADR 0024, ADR 0028).
- The table is a vendored snapshot, not fetched at runtime: a price change is a reviewed diff in a pull request, an instance without internet access has the same prices as ours, and figures do not move unless a commit moved them. A weekly routine runs the script and opens the pull request; it reaches production with the daily release.

## Why

Keeping prices by hand for three providers already took a correction now and then, and every new model waited for us. LiteLLM's list covers the cloud resellers (Bedrock, Vertex, Foundry) we never priced, follows price changes within days, and is open data. Its rows matched our hand-kept table on every Anthropic, OpenAI and Google price but one, where ours was wrong (Claude Sonnet 5.5 cache reads, 0.20 instead of 0.10 per million). With the list public, keeping it out of the open edition protects nothing, so the managed table is no longer an Enterprise or hosted feature, and the Enterprise image no longer fetches prices from the hosted service.

## Consequences

- About 3,300 managed rows instead of about 130. The price table looks rows up by model (`PriceTable` keeps an index), and the table screen has a filter.
- Every request still reads the managed rows with the organization's log, which costs a few milliseconds at this size. If load ever shows it, cache them in memory.
- A message with no provider is priced only when every provider in the table charges the same for its model (ADR 0024). With Vertex, Bedrock and Foundry rows in the table, a message without a provider for a model they also sell can now be not priced yet where it was priced before. Collectors send the provider, so this should stay rare.
- LiteLLM's MIT notice ships in `prices/LICENSE-litellm`.
