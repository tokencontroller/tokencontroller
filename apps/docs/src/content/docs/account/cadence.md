title: "Cadence and token sheets"
description: "Token sheets, cadence and what late means."
---

A token sheet is how a person confirms which ticket each of their sessions was for and what it did. A cadence says how often token sheets are due.

## Token sheets {#token-sheet}

A token sheet holds one agent manager's reviewed token entries for one cadence period. The agent manager reviews the drafts, fixes the ticket where a rule got it wrong, reads the summaries, and submits whenever they like. Cloud and CI token entries never go on a token sheet. Telemetry may already have reported the money of the same sessions; the sheet adds the ticket and the summary, and the two are joined by session ID and counted once.

## Cadence {#cadence}

A people manager can set a cadence for a project or the whole organization: weekly, every two weeks, monthly, or custom. The point is that people report while they still remember what the work was for, not three weeks later.

## Late {#late}

A token sheet whose cadence period is over and that has not been submitted is late. The only consequence is a reminder to its agent manager: one email when it becomes late, and a note in the Claude Code mod and in the web app. Nobody is blocked and nothing is capped. Before the monthly close, the controller can ask everyone to submit, the way finance asks for timesheets before month end. A sheet that comes in after the close is posted to that month as an adjustment, marked late.
