Set up

# .github/workflows/review.yml, after the step that runs your agent
- uses: tokencontroller/action@v1
  with:
    project: storefront
    ticket: ${{ steps.plan.outputs.ticket }}  # optional
    tags: purpose=code-review                 # optional, any tags
    token: ${{ secrets.TOKEN_CONTROLLER_TOKEN }}

Create the service token in the web app under Settings. The person who creates it becomes the agent manager of everything the Action reports.

How CI cost is placed

When the job knows its ticket, pass it as ticket, or set TC_TICKET in an earlier step. That ticket wins over every rule. The Action names the project, and that wins over matching by repository. A review of a pull request is placed on the ticket of that pull request. CI work that matches no ticket falls back to the project. See CI agents.

No review step

Token entries from the Action arrive automatically, with the status submitted. They never go on a token sheet.
