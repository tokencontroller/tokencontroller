The records Token Controller keeps, and the rules that hold between them. For what the terms mean, see Concepts and the glossary.

Records

RecordWhat it holds
OrganizationCost source, attribution target, approval on or off, members and their roles, reporting currency, tag names, tag map.
PersonA member. The default cost center. Carries tags, such as team, that its token entries inherit.
ProjectTags such as client, mapped repositories, ticket key pattern.
TicketSynced from a ticket system or created by hand. A key; optionally a title, a description, a parent ticket and an assignee.
Token entryAgent harness, optional agent name, model, tokens by kind, optional reported cost, list value, billed value, start and end time, summary, agent manager, splits, whether it arrived automatically or on a token sheet, status, evidence.
SplitOne share of a token entry with its own tags. Most token entries are one split.
TagA tag name and a value on a split, a person, a project or a ticket. One value per tag name. Built in: person, ticket, project, kind.
Tag mapWhich tag fills the cost center, the ladder of tags that fills the cost object, and the required tags.
FilterA set of tags. Reports, token budgets and people managers' access are filters.
Token sheetOne agent manager, one cadence period, their reviewed token entries. Submitted or late.
CadenceThe rhythm in which token sheets are due, set per project or organization by a people manager.
Token budgetMoney a human has planned for a filter and a period.
Token forecastMoney suggested for a ticket from similar past work, with the matched tickets and a confidence. Becomes a token budget when a person accepts it.
Telemetry eventOne model call. Joins to token entries by session and message ID.
Cost sourceOne way a provider charges: subscription, seat, usage at API rates, API key, cloud marketplace or reseller.
BillA provider's figure for one period: gross, discount, credit, net, currency and exchange rate, cost source, revision.
PeriodOne calendar month, open or closed.
Cost sheetThe locked account of one closed period, adding up to the bill.
RuleOrdered. Organization rules run before personal ones.

There is no agent record. An agent is whatever caused a token entry, described on the entry by agent harness, agent name and model.

Token entry status

StatusMeaning
DraftStill on the machine, waiting for its token sheet.
SubmittedCounts in reports. Automatic token entries start here.
ApprovedA people manager accepted it. Only used when approval is on.
RejectedSent back to its agent manager with a reason. Does not count until fixed.
LockedIts period is closed.

Rules that always hold

  1. Every cost has a cost center and a cost object.

    Both come from tags through the tag map. The cost center is by default the token entry's agent manager. The cost object is the first rung of the ladder with a value, by default ticket, then project, then organization.

  2. No token entry without an agent manager.

    One that has none shows as an error to people managers until someone takes it.

  3. One value per tag name.

    A split never carries two values of the same tag name, so cost grouped by one tag name adds up to the total.

  4. History stays as it was.

    When an automation gets a new agent manager, or a person, project or ticket changes its tags, only future token entries follow the change. Past splits keep the agent manager and tags they had. A closed period keeps the tag map it closed with.
